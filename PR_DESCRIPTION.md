## Batch processing on Mac, iPhone and iPad

Previously, every image required a separate import, method selection and export. Batch now accepts up to 100 selected photographs and either calculates each from its own whole-image statistics or replays one saved transform unchanged. It saves full-resolution PNG/TIFF/JPEG and optional matching analysis JSON into a fresh folder, preserving sources and existing files. Per-item outcomes reconcile failures, cancellation and partial image/record commits.

Sequential acquisition and checked ownership of full-frame raster allocations prevent the observed growing dirty memory retention while preserving the existing decoder, scientific arithmetic and JSON formats. The independent 3+100-item, 24 MP run produced all 200 final artifacts, original dimensions, empty staging and zero cleanup debt; final settled memory was 232 MB versus a 350 MB three-image maximum. This is a measured settled-memory result, not a universal peak bound for native frameworks or providers.

Validation includes independent Mac Debug 46 affected core + 12 batch tests, optimized 67 core + 43 app tests, iPhone 65 core + 12 batch, iPad 3 decode-policy + 12 batch, 384 exact decoder comparisons and the passing 24 MP benchmark. The independent security and distribution audits passed. Mac native UI/keyboard/VoiceOver/lifecycle coverage remains environment-blocked; native one-second Cancel acknowledgment is inconclusive. Real providers, external crash/cleanup windows, physical-device behavior and TestFlight installation remain unverified. Earlier zoom verification gaps are not superseded. Publication was approved with these limits.
